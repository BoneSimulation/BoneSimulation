## Input Formats

### TIFF Slice Stack

**Location**: `data/bigdataset/` (full dataset) or `data/dataset/` (small test set)

**Format**: Individual single-page TIFF files, one per CT scan slice.

| Property | Value |
|---|---|
| File extension | `.tif` or `.tiff` |
| Naming convention | `slice_NNNN.tif` (zero-padded 4-digit index, e.g. `slice_0032.tif`) |
| Bit depth | 8-bit grayscale (loaded as `uint8` via `Pillow.Image.convert("L")`) |
| Spatial interpretation | Each file is one cross-sectional slice (z-plane) of the 3-D bone sample |
| Ordering | Sorted alphanumerically = spatial z-order |

**How they are used**:

```
data/bigdataset/
├── slice_0001.tif   ← z = 0
├── slice_0002.tif   ← z = 1
├── ...
└── slice_0999.tif   ← z = N-1
```

The loader `load_images_in_chunks` sorts files by name and loads them in batches (default: 50 at a time). All pixel values are in the range [0, 255], where high values typically represent bone tissue (bright) and low values represent air/background (dark).

## Intermediate Formats

### NumPy Arrays (`.npy`)

**Location**: Configurable output directory (e.g., `pictures/`)

Produced by `save_blocks_as_npy` in `image_processing.py`. Each file stores one extracted block as a 3-D binary `uint8` array.

**File naming**: `block_NNNN_<timestamp>.npy`

These files are optional and primarily used for debugging or downstream analysis outside the main pipeline.

## Output Formats

### TIFF Cluster Export

**Location**: `pictures/largest_cluster_<timestamp>.tif`

**Format**: Multi-page BigTIFF, ImageJ-compatible.

| Property | Value |
|---|---|
| Dtype | `uint8` |
| Values | 0 = background, 1 = bone cluster |
| Pages | One page per z-slice of the processed volume |
| Metadata | `imagej=True` (enables loading in ImageJ / Fiji) |

This file contains only the largest connected bone cluster extracted by `cluster_analysis.py`. It can be opened in Fiji/ImageJ, ITK-SNAP, or any TIFF-capable scientific image viewer.

---

### VTK Surface Mesh (`.vtk`, triangular)

**Location**: `pictures/mesh_<timestamp>.vtk`

**Format**: VTK legacy format, triangular surface mesh.

| Property | Value |
|---|---|
| Cell type | `triangle` |
| Vertex coordinates | `float32` |
| Writer | `meshio.write_points_cells` |

Contains the isosurface of the largest bone cluster, extracted by the Marching Cubes algorithm at `level=0.5`. This mesh represents the outer geometry of the trabecular bone structure.

**Viewing**: Open with [ParaView](https://www.paraview.org/), [MeshLab](https://www.meshlab.net/), or PyVista.

---

### VTK Tetrahedral Mesh (`.vtk`, volumetric)

**Location**: `pictures/tetramesh_<timestamp>.vtk`

**Format**: VTK legacy format, volumetric tetrahedral mesh.

| Property | Value |
|---|---|
| Cell type | `tetra` (C3D4) |
| Writer | `ciclope` / `mesh.write()` |

The tetrahedral mesh fills the interior of the bone cluster. It is used as input for the CalculiX FEA simulation. This mesh is generated by CGAL via `ciclope.core.tetraFE.cgal_mesh`, which guarantees quality bounds on facet distance and circumradius.

**Viewing**: Open with ParaView.

---

### VTK ImageData (`.vti`)

**Location**: `pictures/blocks_<timestamp>/block_NNNN.vti`

**Format**: VTK XML ImageData file.

| Property | Value |
|---|---|
| Data array | `"values"` — scalar field on cell data |
| Dtype | `float32` |
| Spacing | `voxel_spacing` (default: 0.05 mm isotropic) |
| Origin | `(0.0, 0.0, 0.0)` |

Each `.vti` file contains one cubic sub-volume block extracted from the full bone cluster. The dimensions are `block_size_voxels × block_size_voxels × block_size_voxels` (default: 600 × 600 × 600 for 30 mm blocks at 0.05 mm/voxel).

**Viewing**: Open with ParaView.

### CalculiX Input File (`.inp`)

**Location**: `calculix/bone_sim_<timestamp>.inp`

**Format**: CalculiX / Abaqus-compatible ASCII text.

This is the primary FEA input file. It is auto-generated by `calculix_export.py` and contains a complete static structural analysis setup.

#### File structure

```
*HEADING
Knochen-Simulation

*NODE
1, x1, y1, z1
2, x2, y2, z2
...

*ELEMENT, TYPE=C3D4
1, n1, n2, n3, n4
2, n1, n2, n3, n4
...

*MATERIAL, NAME=Bone
*ELASTIC
18000.0, 0.3

*SOLID SECTION, ELSET=AllElements, MATERIAL=Bone
AllElements

*ELSET, ELSET=AllElements, GENERATE
1, <N_elements>, 1

*BOUNDARY
<node_id>, 1, 3, 0.0     ← nodes at z=z_min, all 3 DOFs fixed

*CLOAD
<node_id>, 3, <force>    ← nodes at z=z_max, force in z-direction

*STEP
*STATIC
*END STEP
```

#### Key parameters

| Parameter | Value | Description |
|---|---|---|
| Element type | `C3D4` | 4-node linear tetrahedron |
| Young's modulus | 18 000 MPa | Typical cortical bone |
| Poisson's ratio | 0.3 | Typical bone tissue |
| Boundary condition | Fixed at `z = z_min` | All 3 DOFs = 0 |
| Loading | 100 N at `z = z_max` | Distributed equally over all top nodes |

The `.inp` file can also be opened and modified in Abaqus or PrePoMax before running.

### Companion Run Script

**Location**: `calculix/run_simulation.sh`

Auto-generated bash script to invoke the CalculiX solver:

```bash
#!/bin/bash
export OMP_NUM_THREADS=<max_threads>
cd "<absolute_path_to_calculix_dir>"
<solver_binary> -i <basename>
```

Run it with:

```bash
bash calculix/run_simulation.sh
```

CalculiX writes the result files (`.dat`, `.frd`) to the same directory as the `.inp` file.

---

### PDF Analysis Report (`.pdf`)

**Location**: `report/analysis_report_<timestamp>.pdf`

Generated by `reporting.py` using `fpdf2`.

**Contents**:
- Title: "Knochen Analyse Report"
- Number of clusters found in the volume
- Porosity (% of empty voxels)
- Maximum cluster size (voxels)
- Minimum cluster size (voxels)
- Mean cluster size (voxels)
- Cluster-size histogram (PNG embedded in page)

### Log Files

| File | Content |
|---|---|
| `logfile.log` | Timestamped pipeline log at INFO level and above |
| `logs/fault_log.txt` | Python fault handler output (segfault, stack overflow) |

**Log format** (`logfile.log`):

```
2025-06-19 17:12:26,001: INFO : __main__ : Starte Processing Pipeline (test_mode = 'none')
2025-06-19 17:12:26,002: INFO : __main__ : Loading images from: data/bigdataset
...
```

Format string: `%(asctime)s: %(levelname)s : %(name)s : %(message)s`

Both handlers (file + stdout) receive all log levels ≥ INFO by default.
